# TONE3000 in Scythe

TONE3000 (tone3000.com, formerly ToneHunt) hosts Neural Amp Modeler captures and impulse
responses. Scythe's NAM panel can sign in to it, list your favourites, downloads and own tones,
let you pick any tone on the site, and download models into the local library with one click.

This page records what TONE3000's public API offers (as documented at
<https://www.tone3000.com/api> in November 2026) and how Scythe uses it.

## What you need to do once

TONE3000 identifies every app by a **publishable key** (`t3k_pub_…`), which is the OAuth
`client_id`. Scythe does not ship one, so register your own:

1. Sign in on tone3000.com and open **Settings** (<https://www.tone3000.com/settings>), where API
   keys are created. You get a publishable key and a secret key (`t3k_cs_…`).
2. Scythe only needs the publishable key. **Do not** give Scythe the secret key: it is a
   server-only credential and PKCE makes it unnecessary.
3. Either leave the app's redirect URIs empty, or register a fixed loopback URI such as
   `http://127.0.0.1:53682/callback` and tell Scythe to use that port (see below). TONE3000 accepts
   only registered redirect URIs once any are registered, and Scythe otherwise picks a free port
   on every sign-in. Localhost redirects are allowed for development keys.
4. Give Scythe the key, in any of these ways:
   - paste it into the NAM panel's TONE3000 tab (it is saved to the config file), or
   - write `~/.config/scythe/tone3000.json`:
     ```json
     { "client_id": "t3k_pub_…", "redirect_port": 53682 }
     ```
   - or set `SCYTHE_TONE3000_CLIENT_ID` (and optionally `SCYTHE_TONE3000_REDIRECT_PORT`,
     `SCYTHE_TONE3000_BASE_URL`), which override the file.

The free tier is for non-commercial projects (open source, DIY, research) and allows the
select and load-tone flows plus the bounded lists (favourited, downloaded, created, trending,
latest). Search and the bulk zip download need a commercial agreement; Scythe shows TONE3000's
refusal when search is not allowed for the key. TONE3000 asks integrations to be signed off
before a public release.

## Signing in

OAuth 2.0 authorization code flow with PKCE (S256):

- `GET https://www.tone3000.com/api/v1/oauth/authorize` with `client_id`, `redirect_uri`,
  `response_type=code`, `code_challenge`, `code_challenge_method=S256`, `state`, and optionally
  `prompt=select_tone` (pick a tone on the site), `prompt=load_tone&tone_id=…` (open a known
  tone, or pick a replacement if it is gone), `format`, `gears`, `architecture`, `calibrated`,
  `login_hint`, `locale`, `menubar`.
- The redirect carries `code` and `state` (and `tone_id` for the select and load flows; `error`,
  or `canceled=true` when the user closed it).
- `POST /api/v1/oauth/token` (form encoded) with `grant_type=authorization_code`, `code`,
  `code_verifier`, the same `redirect_uri` and `client_id` returns `access_token`,
  `refresh_token`, `token_type=bearer`, `expires_in` and `scope`.
- Refresh: `POST /oauth/token` with `grant_type=refresh_token`, `refresh_token`, `client_id`.
  Refresh tokens rotate: every refresh invalidates the previous one. `invalid_grant` means the
  session is over and the user has to sign in again.
- A device flow (RFC 8628, `/oauth/device_authorization`) exists for devices without a browser;
  Scythe does not need it.

Scythe opens the authorize URL in the system browser (`xdg-open`) and listens on
`127.0.0.1:<port>/callback` for the redirect, checks `state`, exchanges the code and answers
the browser with a short page. The tokens go to `~/.config/scythe/tone3000-session.json`, a file
created with mode 0600 (written to a temporary file with that mode and renamed into place).
Access tokens are refreshed a minute before they expire, and once after a 401; each new pair is
stored at once because of the rotation. "Sign out" deletes the file.

## Endpoints Scythe uses

All need `Authorization: Bearer <access_token>`. Base URL `https://www.tone3000.com/api/v1`.

| Call | Use in Scythe |
| --- | --- |
| `GET /user` | name shown in the TONE3000 tab |
| `GET /tones/favorited`, `/tones/downloaded`, `/tones/created` (`page`, `page_size` ≤ 100) | the list pills |
| `GET /tones/trending`, `/tones/latest` (`{ "data": [...] }`, ten each) | the list pills |
| `GET /tones/search` (`query`, `page`, `page_size` ≤ 25, filters) | search box; tighter limits, commercial keys |
| `GET /tones/{id}` | after the select or load-tone flow |
| `GET /models?tone_id=…` (`page_size` ≤ 300) | a tone's models and impulse responses |
| `PUT` / `DELETE /tones/{id}/favorite` | the star on a tone |
| `GET <model_url>` with the bearer token | downloading one model file |

Not used: `/users`, `/makes`, `/tags` (taxonomy), and `GET /tones/{id}/download` (zip of all
models, approved partners only).

Objects (fields Scythe reads): a tone has `id`, `title`, `description`, `gear` (`amp`, `amp-cab`,
`pedal`, `outboard`, `cab`, `space`, `experimental`), `format` (`nam`, `ir`, `aida-x`,
`aa-snapshot`, `proteus`), `license`, `user` (`username`, `display_name` only for verified
creators), `makes`, `tags`, `sizes`, counts, `is_favorite`, `url`. A model has `id`, `tone_id`,
`name`, `size` (`standard`, `lite`, `feather`, `nano`, `custom`), `model_url`,
`architecture_version` (`1`, `2`, `custom`; null for IRs) and `content_hash`. Lists come as
`{ data, page, page_size, total, total_pages }`.

Rate limits: 100 requests per minute per key by default, search much less; a 429 is reported
with its `Retry-After` when given. TONE3000's design rules for listings (show the creator, the
TONE3000 name, a persistent way to browse the full catalogue) are followed by the TONE3000 tab:
creator names on every tone and "Browse the full catalogue…" (the select flow). Avatars and
the TONE3000 logo are not drawn yet.

## The library

Downloads land in `~/.local/share/scythe/nam/tone3000/<tone id>-<tone title>/<model>.nam` (or
`.wav` for impulse responses), each with a `<file>.t3k.json` beside it holding the tone id, model
id, title, creator, gear, makes, URL and licence, so the library can be rebuilt from the folder.
`~/.local/share/scythe/nam/library.json` keeps the index (name, author, gear, architecture,
sample rate, origin), the added folders, favourites, tags and recently used models. Added
folders (such as `~/music/Samples/NAM`) are only read, never written.

## Tests

`crates/scythe-app/src/nam/tone3000.rs` tests the client against recorded responses in
`crates/scythe-app/tests/fixtures/tone3000/` behind a fake `Http`: no test touches the network,
and the loopback redirect is exercised with a local socket only. The response shapes follow the
documentation above; they have not been checked against live traffic yet.
