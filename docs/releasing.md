# Releasing Scythe

A release is a draft GitHub release that the `Release` workflow (`.github/workflows/release.yml`)
makes when a tag `v<version>` is pushed. Scythe and the ScyEQ-Pro plugin share the workspace
version and are released together.

## What a release contains

| File | Contents |
|---|---|
| `scythe-<version>-linux-x86_64.tar.gz` | `scythe-app`, `scythe-server` and `scythe-mcp`, built on Ubuntu 22.04 so they run on distributions with glibc 2.35 or newer |
| `scythe-<version>-windows-x86_64.msi` | the installer from `crates/scythe-app/wix/main.wxs` (see the README's Windows section) |
| `scythe-<version>-windows-x86_64.zip` | the same three programs, without installing |
| `scythe-<version>-macos-universal.zip` | `Scythe.app` for Apple silicon and Intel (beta, see below) |
| `ScyEQ-Pro-<version>-<os>.zip` | the plugin for `linux`, `windows` and `macos`, from the `ScyEQ-Pro plugin` workflow ([crates/scyeq-plugin/README.md](../crates/scyeq-plugin/README.md)) |
| `SHA256SUMS` | the checksum of every file above |

Every archive carries `LICENSE-MIT`, `LICENSE-APACHE`, `THIRD_PARTY_NOTICES.md`, the fonts'
`Inter-OFL.txt` and `JetBrainsMono-OFL.txt`, and `CRATE_LICENSES.md`: the license of every crate
built into it, with the license texts, generated by
[cargo-about](https://github.com/EmbarkStudios/cargo-about) for that program and platform.
`about.toml` lists the licenses accepted; a dependency under any other license fails the build
until its license has been looked at and added there. The MSI installs the same files in its
install folder, above the programs' `bin`.

Release builds leave out the `asio` feature (see "Licensing notes" in the README), so the
Windows build plays through WASAPI.

## Cutting a release

1. Set the new version under `[workspace.package]` in `Cargo.toml`, let Cargo update
   `Cargo.lock` (`devbox run build`), and commit both on `main`.
2. Optionally try the builds first: Actions > Release > Run workflow on `main`. A run by hand
   builds everything and keeps the files, with `SHA256SUMS`, as the run's `release-<version>`
   artifact; it makes no release.
3. Tag the commit and push the tag:

   ```sh
   git tag -a v0.2.0 -m "Scythe 0.2.0"
   git push origin v0.2.0
   ```

   The workflow's first job fails when the tag is not `v` followed by the workspace version.
4. When the workflow is done, open the draft under Releases. Check that every file above is
   there, and edit the notes GitHub generated from the merged pull requests and commits.
5. Publish the draft.

A failed run makes no release. Fix the cause on `main`, then move the tag to the fixed commit
(`git tag -f -a v0.2.0 -m "Scythe 0.2.0"`, `git push -f origin v0.2.0`) or release the next
version.

The ScyEQ-Pro plugin depends on [plugin-format](https://github.com/tluijken/plugin-format) at a
tag; `PLUGIN_FORMAT_TAG` in `.github/workflows/scyeq-plugin.yml` names the same tag, for its
bundle and validation scripts, and changes with it.

## Building a release locally

`scripts/release/package.sh <out dir>` is what the workflow runs on each system: it builds the
three programs in release and writes the archives for the system it runs on. It needs
`cargo-about` on the `PATH`; on Windows also `cargo-wix`, WiX 3 and 7-Zip, run from Git Bash.

```sh
devbox run -- scripts/release/package.sh dist   # dist/scythe-<version>-linux-x86_64.tar.gz
```

What it writes locally is for checking the packaging, not for handing out: built in devbox, the
Linux programs load their libraries through Nix's dynamic loader under `/nix/store`, so they run
only on a machine with that store, not on an ordinary distribution. Releases come from the
workflow, which builds on the runners' own systems.

`scripts/release/notices.sh <dir> <crate> <os> [features]` alone writes the licenses and
`CRATE_LICENSES.md` for one crate built with those cargo features, for example to check
`about.toml` after adding a dependency.

## macOS (beta)

The macOS build is signed ad hoc and not notarized: notarizing needs an Apple Developer account,
which comes later. macOS blocks the app the first time it is opened. Allow it once under System
Settings > Privacy & Security (Open Anyway), or remove the quarantine flag after moving it to
Applications:

```sh
xattr -dr com.apple.quarantine /Applications/Scythe.app
```

`scythe-server` and `scythe-mcp` are inside the app, in `Scythe.app/Contents/MacOS/`.

The ScyEQ-Pro plugin's macOS zip is signed and blocked the same way; its README says how to allow
it.
